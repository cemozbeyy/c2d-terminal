How to run several Claude Code sessions at once on a Mac

Two Claude Code sessions in the same folder will edit the same files and trip over each other. The fix is to give each session its own checkout. Git worktrees do that without cloning the repository again.

Updated 29 October 2026 · Written by the makers of C2D Terminal

1. One worktree per session

Claude Code can create the worktree for you. In one terminal:

claude --worktree feature-auth

In a second terminal, the same command with another name starts an isolated parallel session:

claude --worktree fix-login-bug

Each worktree is a separate checkout on its own branch, created from an existing commit, so the repository needs at least one commit first. If you prefer to manage worktrees yourself, plain git works too:

git worktree add ../myapp-auth -b feature-auth
cd ../myapp-auth && claude

When a branch is merged, remove its folder with git worktree remove ../myapp-auth.

2. Pick up where a session left off

claude --continue     # resume the most recent session in this folder
claude --resume       # choose from a list of earlier sessions

Because sessions are stored per folder, a separate worktree also keeps each session's history separate.

3. Know when a session needs you

Claude Code sends a desktop notification when it finishes or waits for a permission prompt, by default in Ghostty, Kitty and iTerm2. In other terminals, set "preferredNotifChannel": "terminal_bell" in ~/.claude/settings.json to get a bell instead. See the terminal setup guide for details.

4. Review each branch on its own

Parallel sessions mean parallel diffs. Review and commit each worktree separately, with the steps in How to review Claude Code's changes before you commit, and merge only what you have read.

In C2D Terminal the pieces above sit in one window:
