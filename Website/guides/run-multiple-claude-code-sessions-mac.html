How to run several Claude Code sessions at once on a Mac

Two Claude Code sessions in the same folder will edit the same files and trip over each other. The fix is to give each session its own checkout. Git worktrees do that without cloning the repository again.

Updated 29 October 2026 · Written by the makers of C2D Terminal

1. One worktree per session

Claude Code can create the worktree for you. In one terminal:

claude --worktree feature-auth

In a second terminal, the same command with another name starts an isolated parallel session:

claude --worktree fix-login-bug

Claude Code puts each worktree in .claude/worktrees/<name>/ at the repository root, on a new branch called worktree-<name>, branched from your default branch. The repository needs at least one commit first. Add .claude/worktrees/ to your .gitignore so the folders don't show up as untracked files in your main checkout.

Set up each worktree

A worktree is a fresh checkout, so install dependencies there (or ask Claude Code to). Gitignored files such as .env are not copied by default. List them in a .worktreeinclude file at the project root, using .gitignore syntax, and Claude Code copies them into every new worktree:

.env
.env.local

Or manage worktrees with plain git

Use git directly when you want a specific existing branch or a folder outside the repository:

git worktree add ../myapp-auth -b feature-auth
cd ../myapp-auth && claude

See what you have with git worktree list, and remove a folder when its branch is merged with git worktree remove ../myapp-auth.

What happens when you exit

When you leave a --worktree session, Claude Code checks the worktree for changes, untracked files and new commits. A clean worktree from an unnamed session is removed with its branch. If there is work in it, Claude Code asks whether to keep it, and prints a claude --worktree <name> --resume command to come back to it later.

2. Pick up where a session left off

claude --continue     # resume the most recent session in this folder
claude --resume       # choose from a list of earlier sessions

Because sessions are stored per folder, a separate worktree also keeps each session's history separate. Permission approvals are shared, though: "Yes, and don't ask again" in any worktree is saved to the main checkout's .claude/settings.local.json and applies to every worktree of the repository.

3. Know when a session needs you

Claude Code sends a desktop notification when it finishes or waits for a permission prompt, by default in Ghostty, Kitty and iTerm2. In other terminals, set "preferredNotifChannel": "terminal_bell" in ~/.claude/settings.json to get a bell instead. See the terminal setup guide for details.

4. Review each branch on its own

Parallel sessions mean parallel diffs, and two sessions that edit the same files will still conflict when you merge. Review and commit each worktree separately, with the steps in How to review Claude Code's changes before you commit, and merge only what you have read.

Doing the same in C2D Terminal

In C2D Terminal the pieces above sit in one window:

  • Several projects stay open as pages, so each repository or worktree can have its own workspace and layout.
  • The Git panel handles branches and worktrees.
  • Each Claude Code launch runs in its own real terminal, rooted in the project you picked, and gets its own session id. You can hand it a task as the first prompt.
  • Terminal windows have native tabs and split panes, so tests and dev servers run next to the agent.
  • Token Saver shows token usage per project and per session, read from Claude Code's own local transcripts.
